sync upstream c62d0bc: restore missing credit APIs; fix TraeWork callback

## Why
The addon was pinned to upstream ad32896 while upstream HEAD is c62d0bc. Comparing
packages showed the same group of credit-related functions missing from ALL THREE
channel packages, which explains both reported symptoms:
  - WorkBuddy credits unusable (upstream pkg lacks UserResourceDetail,
    FetchModelPricing, parseCredits)
  - TraeWork works in the official client but not here (client ships its own code;
    the addon lacked UserResourceDetail/FetchModelPricing/parseTraeFeatures)

Crucially this was a SILENT degradation: provider.Upstream was still the old
8-method interface, so the Clients compiled fine without the two new methods and
credit capability was simply absent (no build error).

## Changes
- Targeted sync of upstream c62d0bc for: traework, upstream, qoder, provider
  (18 files; import path rewritten to the addon module like sync_vendor.sh does).
  pool/server/scheduler untouched on purpose to keep the blast radius small.
- provider.Upstream is now the 10-method interface (adds FetchModelPricing and
  UserResourceDetail); the three channel Clients satisfy it after the sync.

## UPSTREAM BUG FIXED HERE (upstream c62d0bc does not compile)
Upstream commit c62d0bc accidentally deleted "var resp struct {" from

building the upstream repo itself fails with
  internal/traework/client.go:469:28: syntax error: unexpected ], expected operand
Restored the missing declaration here so the addon compiles.

## TraeWork login (root cause is a stale image, not the code)
- addon_extras.go: drop the "/authorize" suffix from the public callback
  (the panel endpoint is /api/trae-cb itself; adding /authorize 404s) and set
  redirect=0, matching the known-good desktop/trae2api-web flow.
- login_ui.py: after opening the auth link, auto-poll trae-poll so login completes
  itself when the callback lands; manual paste and refreshToken remain as fallbacks.
- Verified in the running container: the OLD (Aug 27) logintrae binary emits a
  127.0.0.1 callback and ignores -callback, while a binary rebuilt from this source
  emits the public callback (auth_callback_url=http://.../api/trae-cb, redirect=0).
  So the login code is correct; the deployed image must be rebuilt for it to take
  effect.
